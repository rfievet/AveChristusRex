# UI/UX pass on Ave Christus Rex: in-topic filter bar, copy/share, PWA, and light/dark theme

This pass adds four behavioral features to the apologetics site: a sticky in-topic jump + strength-filter bar on the topic page, per-argument Copy/Link actions, Open Graph/Twitter social meta plus a full PWA (installable, offline-cached), and a class-based light (parchment) / dark (ink) theme with an accessible NavBar toggle. The theme work was done first because it is cross-cutting and sets the color conventions every other feature follows: author the light value as the base utility and keep the old dark value behind a `dark:` variant. All of it stays data-driven, so later-added topics and arguments render with no code change. Watch for: nothing blocking — the sticky-offset and scroll-mt values that the integration commit had to reconcile across three components (NavBar height, filter bar, section headings) are the one place where a future height change could silently hide a jumped-to heading (confirmed, and currently consistent).

**Verdict**: APPROVED

## High-level view

The theme system is the spine of the change. Tailwind `darkMode: 'class'` is driven by a `dark` class on `<html>` that a synchronous inline script in `index.html` sets before React paints, reading `localStorage['theme']` then falling back to `prefers-color-scheme`. Every component was converted to a light base + `dark:` override, so neither theme has an invisible or low-contrast element. The NavBar toggle reads its initial state from the DOM class the inline script already applied, so there is no hydration flash.

The in-topic filter bar is fully data-driven: chips and per-section counts derive from the same `visibleSections` list that renders the sections, and strength filtering recomputes counts and drops empty sections. The one coupling to watch is the sticky-offset stack — NavBar (`top-0`) + filter bar (`top-[69px]`) + heading `scroll-mt-48` — which the integration commit had to align; it is currently consistent and verified in the compiled CSS.

Per-argument Copy builds a plain-text citation block (`title`, each ref as `<citation> (<translationUsed>) — <text>`, then `shortClaim`) and Link builds `${origin}/topic/${topicId}#${id}` with a pathname fallback; both go through a clipboard hook with an `execCommand` fallback and surface an `aria-live` confirmation. The deep-link format matches the search modal's route, and a dedicated effect resets the strength filter to `all` whenever a hash is present so a filtered-out card is never unreachable.

The PWA is a static `public/manifest.webmanifest` as the single source of truth with `vite-plugin-pwa` (pinned exactly `0.21.1`) generating only the service worker, `navigateFallback` to the SPA shell, and `devOptions.enabled:false` so the running dev server on 5317 is untouched. The server/preview blocks (host `0.0.0.0`, port `5317`, `strictPort`) are unchanged.

### Theme system: class-based, light-base + dark-override, no-flash

The non-obvious design choices worth recording: the authoritative state is the `dark` class on `<html>`, set by an inline script that runs before paint, so the dark default never flashes the light base; and the conversion keeps the readable light value as the base utility with the prior dark value behind `dark:` (`text-ink-900 dark:text-parchment-50`, `bg-parchment-50 dark:bg-ink-800/40`). `:focus-visible` switches its ring-offset color per theme so the focus ring reads in both. The compiled CSS emits 138 `.dark` rules, confirming the override set survived the build rather than being tree-shaken.

`StrengthBadge` is the one component where contrast needed per-strength attention: `scriptural` stays solid gold-400 on ink-900 (legible both ways), while `strong` and `supplementary` each got a light base plus a `dark:` override. The NavBar toggle initializes `useTheme` from the DOM class the inline script already set, so the button state matches what the user sees with no hydration flash; it carries `aria-pressed` + a theme-flipping `aria-label` and persists to `localStorage['theme']`.

### In-topic filter + jump bar: data-driven, with a sticky-offset coupling

```
TopicPage
  order (declared categories ∪ arg categories)
  grouped: Map<category, Argument[]>
      │  filter by activeStrength, drop empty
      ▼
  visibleSections ──┬── filterSections → <TopicFilterBar/>   (chips + counts)
                    └── rendered <section> list              (headings + cards)
```

Chips, counts, and rendered sections all derive from the same `visibleSections`, so there is no hardcoded category list — a later-added category or argument appears automatically. Strength selection recomputes each section's filtered count and omits sections that empty out.

The sticky stack is the part worth tracking. NavBar is `sticky top-0`, the filter bar `sticky top-[69px]`, section headings `scroll-mt-48` so a chip jump clears both layers. The integration commit is where these were reconciled — filter bar `top-[56px]`→`top-[69px]`, heading `scroll-mt` `44`/`24`→unified `48`, `ArgumentCard` `scroll-mt-24`→`scroll-mt-48` — and the `top:69px` / `scroll-mt-48` rules are present in the compiled CSS. These three values are coupled: if the nav or bar height changes later they must move together, or a jumped-to heading will sit behind the sticky bars. The chip/strength rows are `flex gap-2 overflow-x-auto` on mobile, every chip/toggle is `min-h-[44px]`, and the bar's negative margins (`-mx-4 … sm:-mx-6`) span its background without widening the page at 360px.

### Copy / Link: citation block, deep link, and the hash-filter interaction

Copy assembles `title`, each `primaryReferences` entry as `${ref.citation} (${ref.translationUsed}) — ${ref.text}`, then `shortClaim`. Link builds `${origin}/topic/${topicId}#${id}` with a `${origin}${pathname}#${id}` fallback when `topicId` is undefined — matching the route the search modal deep-links to, so a pasted link resolves to the hash-scroll + `.search-flash` effect. `topicId` is an optional component prop; `src/data/types.ts` shapes are unchanged (only a brand-name comment edit). `useCopy` uses the async Clipboard API with a `<textarea>` + `execCommand('copy')` fallback for insecure contexts, and surfaces confirmation both as a visually-hidden `aria-live="polite" role="status"` span and a `motion-safe:`-only visible pill.

The non-obvious correctness point: strength filtering could otherwise hide a card a deep link targets. A dedicated effect runs `if (hash) setActiveStrength('all')` before the (unchanged) hash-scroll effect, guaranteeing the target card is rendered before the scroll+flash fires.

### PWA + social meta: static manifest, SW-only plugin, dev server untouched

The design choice: a static `public/manifest.webmanifest` is the single source of truth and `vite-plugin-pwa` runs with `manifest: false`, so it only generates the service worker. `navigateFallback: '/index.html'` serves the SPA shell, and `devOptions.enabled: false` keeps the already-running dev server on 5317 out of the plugin's path. The plugin is pinned to an exact `0.21.1` (no caret). The build emits `dist/sw.js`, `dist/workbox-*.js`, and `dist/registerSW.js` (11 precache entries), icon dimensions verified at 192×192 / 512×512 / 180×180, and `index.html` carries the manifest link plus OG and Twitter summary meta (`og:url` omitted — no production domain yet).

### Scope and constraints held

The server and preview blocks in `vite.config.ts` keep host `0.0.0.0`, port `5317`, and `strictPort: true` exactly. No file under `src/data/content/**` or `.agents/research/**` was edited by any UI-pass commit (only the initial repo-creation commit touches content, which predates this pass). The only `src/data/types.ts` change is a one-line comment correcting the brand name. "Ave Jesus Rex" appears only inside `.agents/tasks/**` tracking notes and the repo folder name — no shippable source or the built `dist/index.html` contains it; the brand reads "Ave Christus Rex" throughout. `npm run typecheck` and `npm run build` both exit 0 under strict TypeScript.
